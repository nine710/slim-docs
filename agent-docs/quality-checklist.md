# 反模式与发布检查表

## 反模式

| 反模式 | 为何有害 | 改法 |
|--------|----------|------|
| 巨型 SKILL.md 百科 | 激活即爆上下文；关键步骤被淹没 | &lt;500 行；细节下沉 references |
| description 写满流程 | 模型跟摘要、跳过正文 | description 只写触发条件 |
| 嵌套引用链 | 部分读取、信息残缺 | SKILL.md 一层直达 |
| 叙事型「我们那天修了…」 | 不可复用 | 提炼为步骤/gotcha |
| 五语言半吊子示例 | 维护成本、质量稀 | 一个可运行精品示例 |
| 空泛 name（utils/helper） | 无法路由 | 动名词/领域专名 |
| 与模型已会能力重复 | 浪费 token | 只写 delta |
| skill 内 README/CHANGELOG 当依赖 | 污染包、非 agent 接口 | 人读文档放仓库 docs，不放运行时路径 |
| 深层 Windows 路径 | 跨平台失败 | 相对路径 + `/` |
| 选项过多无默认 | 决策瘫痪 | 给默认路径 + 一条逃逸分支 |
| 无验证完成 | 假完成 | 命令/脚本证据门禁 |
| 第三方 skill 盲装 | 供应链/注入风险 | 审 scripts 与外联 |

## 合规结构检查

- [ ] 目录名 = `name` = kebab-case  
- [ ] 存在 `SKILL.md`，YAML 含 `name`、`description`  
- [ ] description 第三人称 + what/when（建议负向触发）  
- [ ] 可选 `scripts/` `references/` `assets/` 职责不混  
- [ ] 引用一层深；长文有 Contents  
- [ ] 无密钥；破坏性操作有确认或明确范围  

## 质量检查

- [ ] 打开 skill 后 30 秒能看出主流程  
- [ ] 有明确完成标准或验证命令  
- [ ] Gotchas 来自真实失败，非臆造  
- [ ] 与 CLAUDE.md/AGENTS.md 不重复堆同一长文  
- [ ] 触发正/负例想过至少各 2 条  

## 「优秀」快速画像

来自官方与高星实践的交集：

1. **可发现**：description 像路由表  
2. **可执行**：步骤/门禁/模板，不是感想  
3. **可负担**：渐进披露，激活成本可控  
4. **可验证**：脚本或 eval，不靠自觉  
5. **可演进**：gotcha 与 eval 随真实失败增长  
6. **意图不惊喜**：包内无隐藏恶意或名不副实行为  

## 安全底线

- skill 可含 shell：安装前当代码审  
- 不创建「看起来像 X、实际做 Y」的误导包  
- 用户指令 &gt; skill &gt; 默认系统行为（冲突时尊重用户与仓库入口文件）
